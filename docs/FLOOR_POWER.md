## 2. 每层统计表

### 2.1 先说清楚「层」是什么

- `f` 是 mod 自己的层序数（`state.floorDepth`），换层时 +1，也就是册子 UI 上那个 `Floor N`。
- 存档里的 `LevelStage` 字段**不可靠**：同一层段里记录的 stage 会跳变/重复（例：`f=2` 记到 `2/0`，`f=3` 记到 `2/4`），
  所以本报告**不用 stage 命名楼层**，只按序数 `f` 谈。原始底稿 §D 保留了这些记录值供核对。
- **层段完整性**：一个真实楼层只有一个 Boss 房。用「同一段 `f` 里出现 ≥2 个首访 Boss 房」判断是否卷了多层：

任务里提到的 `resources\entities2.xml` **在本机不存在**。实际情况：

### 3.5 局限（照抄进任何引用本报告的地方）

1. **不是原版数据**：原版 `entities2.xml` 在加密归档里，本报告用的是 mod 文件，样本偏向「装了 60+ mod 的这套环境」。
2. **不含「哪层出现哪个怪」**：`entities2.xml` 只有实体定义，`resources/rooms/*.stb`（房间刷怪表）也在归档里，本地只有一个 8 字节的空文件 → **「每层平均怪血」在本地不可能算准**。
3. **mod 怪未覆盖**：mod 用 Lua 动态生成/改血的怪不会体现在 xml 里；champion（精英）倍率也没算。
4. **哨兵值污染**：不清洗的话均值完全失真（见 §3.3）。

## 4. 口径 A：经验法（用真实受伤/时长反推「够用」）

### 4.0 战力是什么单位

采集用的是 [`mod-review/core/power_forms.lua`](../mod-review/core/power_forms.lua) 的新口径：

```
POWER = 伤害 × 射速 × 形态系数 × 道具乘区 × 宝宝倍数
      = D × 30/(MaxFireDelay+1) × … × Πmult × (1+Σ宝宝)
```

即**「整队等效 DPS」**（乘区按满命中假设，例如死眼 1.91、书虫 1.5、宝宝套 1.5）。
所以它**大于**单发面板 DPS：底稿里 `p/(dv×ts)` 的比值随层数从 1.00× 涨到 1.75×（后期道具乘区变多），
极端样本（妈刀形态）能到 5.2×。做血量/时长换算时，这个「满命中假设」会让口径 B 偏高（见 §5.5）。

基线参考：以撒空手 `3.5 × 30/11 = 9.5455`，本样本开局战力中位 **9.55**，对得上。

## 5. 口径 B：血量法（`怪数 × 平均怪血 ÷ 每房击杀时间`）

### 5.1 公式与假设

```
需要的 DPS（≈ 战力） = ( 每房怪数 N × 平均怪血 H ) ÷ 每房击杀时间 T
```

- `H` 有实测（§3.3：普通怪中位 20 / P75 32.5 / P90 50；Boss 中位 300）。
- `T` 有实测（§5.2：零伤清房时长，中位 5.4~16.6 s）。
- **`N` 没有**（§2.5）。所以下面给的是**敏感性表**，不是点估计。

另外给一个**反推量**：`隐含每房总血量 = 该层 p 中位 × 该层零伤清房时长`。
含义：按 100% 命中、无走位、无空档算，这间房至少要掉这么多血。因为它假设太理想，**是上界**。

### 5.5 口径 B 的两个系统性偏差（必须写进货）

1. **偏高**：`隐含血量` 假设 100% 命中；战力的乘区（死眼 1.91 之类）按满命中折算。
   实际上玩家要躲弹、要跑位、怪还会分散 —— 站桩输出效率**假设**只有 50%~70%。
   → 用「N=5, H=35」这档更接近真实（f=6 约 25、f=9 约 33），比 `隐含血量÷时长` 低一半左右。
2. **偏低**：`H` 取的是**全体 mod 怪中位 20 血**，这是全样本的中位数（低血小怪占大头）；
   而中后期怪普遍更肉（直方图里 31 血以上的实体占 **36%**，626/1720）。
   如果中后期房间以这些为主，真实 `N×H` 会明显高于「N=5, H=20」那一档，更接近「N=5,H=35」或「N=7,H=60」。
   **两个偏差方向相反、量级相当，正好互相抵消一部分**，这也是为什么最终结论只能用「±50%」这种粗表述。

## 8. 复现方式

```powershell
# 32 位 PowerShell（游戏的 Lua5.4.dll 是 x86），在仓库根目录执行
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File D:\00000\aiStudy\issacmod\tools\luarun.ps1 D:\00000\aiStudy\issacmod\tests\floor_power_stats.lua
```

- 脚本：[`tests/floor_power_stats.lua`](../tests/floor_power_stats.lua)（只读；存档路径由 `tools/luarun.ps1` 写进 `_logs/.hlr_paths.lua`，不硬编码）
- 输出：`_logs/floor-power-<时间戳>.txt`，含 A~I 九段底稿：
  `A` 数据源 / `B` 概览 / `C` 每层表 / `C2` 层段完整性 / `D` 三分位 + 舒适带 / `E` 战力口径核对 /
  `F` entities2 血量 / `G` 口径 B 原料 / `H` 房间类型 / `I` 明细
- 口径定义（脚本里的实现）：
  - **首访** = 记录里 `first=1`（`MC_POST_NEW_ROOM` 时判断该房是否本局首次进入）
  - **进层战力** = 该「局·层」内 `min(p)`；**出层战力** = 该段内 `max(po)`
  - **零伤清房** = `dmg == 0 and clr == true`
  - **并段** = 同一 `f` 内首访 Boss 房（`t == 5`）≥ 2 个
  - **哨兵血量** = `baseHP ≥ 1000`
- 枚举名（房型 / 关卡）在运行时从 `<游戏>/resources/scripts/enums.lua` 现读，不在脚本里硬编码。
